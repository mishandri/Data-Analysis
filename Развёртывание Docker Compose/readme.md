# Развёртывание Docker Compose: Nginx + Python + PostgreSQL

Docker, Docker Compose, Nginx, Python, PostgreSQL 17.

## Задача

Поднять многоконтейнерное приложение одной командой, с постоянным хранением данных и веб-доступом к результату. Схема вычислительный слой, хранилище, обратный прокси повторяется почти в каждом внутреннем аналитическом сервисе.

## Три контейнера

```
        ┌────────────┐
        │    Nginx    │  8080 → 80, раздаёт HTML
        └──────┬─────┘
               │ volume html_data
       ┌───────▼──────┐      ┌───────────────┐
       │  Python app   │─────▶│  PostgreSQL   │
       │  пишет HTML   │      │  analytics_db │
       └───────────────┘      └───────────────┘
               └──── volume pg_data ────┘
```

Контейнеры в общей сети `my_net`, общаются по именам сервисов.

**Python.** `my_python_app`, сборка из `./python_app`. Генерирует HTML, зависит от PostgreSQL, автоперезапуск.

**PostgreSQL.** Образ `postgres:17.7`, база `analytics_db`, пользователь `user`. Порт 5432 внутри и 7777 снаружи. Данные в volume `pg_data`, пересоздание контейнера их не уничтожает.

**Nginx.** Образ `nginx:latest`, порт 80 внутри и 8080 снаружи, свой `nginx.conf`, статика из общего volume `html_data`.

Внешние порты нестандартные, 8080 и 7777 вместо 80 и 5432, чтобы не конфликтовать с локальной БД и локальным сервером.

## Про пароль

Пароль лежит в `.env`, а не в репозитории и не в коде.

```
docker-compose.yml   ${POSTGRES_PASSWORD:?задайте POSTGRES_PASSWORD в .env}
.env                 реальное значение, в git не попадает
.env.example         шаблон с именами переменных, в git нужен
```

В `docker-compose.yml` используется синтаксис `${ПЕРЕМЕННАЯ:?текст}`. Если переменная не задана, Compose не запустится с текстом `задайте POSTGRES_PASSWORD в .env`, а не подставит пустую строку и не создаст базу с пустым паролем. Для учётных данных второй вариант опаснее.

В Python пароль читается из переменной окружения:

```python
DB_CONFIG = {
    'password': os.environ['PGPASSWORD'],   # KeyError, если не задана
    ...
}
```

Квадратные скобки, а не `.get()`, намеренно: лучше упасть при старте с понятной ошибкой, чем подключиться не к той базе. Внешних зависимостей не добавляет.

Дополнительно: `INSERT` переведён с f-строки на параметризованный запрос. В наименованиях товаров встречаются апострофы, и любая из них рвала всю вставку. Это была реальная ошибка, а не теоретическая.

## Запуск

```bash
cp .env.example .env     # подставить свой пароль
docker-compose up -d
```

Дальше `http://localhost:8080`, PostgreSQL доступен на `localhost:7777`.

## Переменные

| Переменная  | Куда                          | По умолчанию        |
| --------------------- | --------------------------------- | ------------------------------ |
| `POSTGRES_USER`     | БД и приложение      | `user`                       |
| `POSTGRES_PASSWORD` | БД и приложение      | нет, обязательна |
| `POSTGRES_DB`       | БД и приложение      | `analytics_db`               |
| `PGHOST`            | только приложение | `postgres-db`                |
| `PGPORT`            | только приложение | `5432`                       |

Приложение получает `PG*` через секцию `environment` того же сервиса. Это стандартные имена переменных для `psycopg2`, поэтому конфигурация приложения читается без правок при смене окружения.

## Volumes и сеть

| Ресурс     | Назначение                                                   |
| ---------------- | ---------------------------------------------------------------------- |
| `pg_data`      | постоянное хранение данных PostgreSQL          |
| `html_data`    | общий том между Python-приложением и Nginx    |
| `./nginx.conf` | конфигурация Nginx, смонтирована с хоста |
| `my_net`       | bridge-сеть, общение по именам сервисов     |

## Что показывает проект

- Понимание контейнеризации на уровне сетевого взаимодействия: общая сеть, обращение по именам сервисов, health-зависимости.
- Знание volumes: разница между обменом внутри контейнеров и персистентным хранением, а также монтированием файлов конфигурации с хоста.
- Работа с обратным прокси: приложение генерирует артефакт, Nginx его раздаёт.
- Обращение с секретами: пароль в `.env`, обязательная проверка на старте, никаких значений по умолчанию для паролей.
- Параметризованные SQL-запросы вместо конкатенации строк.
