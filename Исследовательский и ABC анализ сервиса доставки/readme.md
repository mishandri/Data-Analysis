# Исследовательский и ABC-анализ сервиса доставки

Тестовое задание на позицию продуктового аналитика. Pandas, NumPy, Seaborn.

ТЗ в [Описание.md](Описание.md), решение в `Решение.ipynb`.

## Данные

`products`: `product_id`, `level1` (категория), `level2` (подкатегория), `name`.

`orders`: `order_id`, `accepted_at`, `product_id`, `quantity`, `regular_price`, `price`, `cost_price`.

Таблицы соединяются через `merge` по `product_id`. По условию задачи, кроме расчёта среднего чека, товары из `orders`, которых нет в `products`, можно не учитывать.

## Решения

Самая ходовая товарная группа определяется через `groupby('level1')['quantity'].sum()`. На графике лидирующий столбец выделен цветом, иначе при 30+ категориях подпись теряется.

Распределение по подкатегориям считается через `groupby(['level1', 'level2'])`.

Средний чек за 13.01.2022 считается так: фильтр по дате, затем сворачивание до уровня `order_id` как сумма `price × quantity`, и только после этого среднее по чекам. Если усреднить по позициям, длинные чеки перевесят короткие и результат будет другим.

Промо определяется сравнением `regular_price != price`, а не флагом из справочника. Промо-механика меняется чаще, чем схема данных, и сравнение цен переживает такие изменения.

Маржа считается отдельной функцией `calc_margin`, которая возвращает `pd.Series` с маржой в рублях и маржинальностью в процентах. Через `groupby().apply()` сразу получается таблица под горизонтальный барчарт.

ABC делается по подкатегориям. Каждая метрика переводится в долю, сортируется по убыванию, считается кумулятивная сумма, и по порогам 0.8 и 0.95 ставится A, B или C. Две классификации объединяются в сводную группу вида `A C`.

Уровень анализа выбран не по привычке. В условии прямо сказано, что данных за короткий период не хватит для честного анализа по отдельным товарам, а товаров слишком много. ABC по подкатегориям даёт картину, в которой видно решение, а не разбивку на тысячи SKU.
