# Рекомендации безлимитных тарифных опций

ClickHouse, CTE. Данные: трафик абонентов `data_traffic` и тарифные пакеты `packet`.

## Задача

Собрать список абонентов, которым имеет смысл предложить безлимитный тариф, на основе превышения лимитов.

## Настройки

`packet_start_date`, по умолчанию `'2024-09-01'`, и `passed_days`, по умолчанию 10.

## Логика

Шаг первый, трафик по опциям. Соединяются трафик и справочник пакетов, фильтруется по дате и по ненулевому лимиту, затем группировка по абоненту, опции и лимиту с суммой трафика в МБ.

Нулевые лимиты отсекаются здесь. У безлимитных опций лимита нет, и оставлять их в расчёте превышения бессмысленно.

Шаг второй, самая затратная опция. Для каждого абонента берётся опция с максимальным потреблением. Записи с `Unknown` исключаются, иначе абонент с потерянным маппингом получил бы рекомендацию по опции, которой у него нет.

Шаг третий, прогноз. Трафик суммируется по всем опциям, среднедневное потребление пересчитывается на месяц, считается коэффициент превышения лимита `ratio`.

Шаг четвёртый, отбор. Остаются абоненты с `ratio > 1`.

## Что отдаёт запрос

`account_id` и `top_option_by_spend_mb`, то есть абонент и конкретная опция, которую ему предлагают. Без второго поля отдельно на продажников не отправишь.

## Слабое место прогноза

Прогноз на месяц строится как средний день умноженный на 30. Это допущение, и оно хрупкое: недельная и сезонная структура трафика в него не попадает. Если у абонента есть отпуск, дача или просто разовая активная неделя, он получит неверную рекомендацию. Для продакшена стоит считать проекцию по профилю похожих абонентов, а не по своему же среднему.
